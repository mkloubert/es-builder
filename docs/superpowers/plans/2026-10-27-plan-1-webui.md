# Plan 1: Web service `emulationstation-web` – Implementation Plan

License: AGPL-3.0-or-later, see LICENSE

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single Go binary that serves a Tailwind web UI over HTTPS on `0.0.0.0:11944` to control the device and EmulationStation (ROM upload, names, scraping, BIOS, controllers, Bluetooth, system).

**Architecture:** Domain logic lives in small `internal/` packages without HTTP dependencies (each package has its own tests with fixtures/fakes); `internal/web` wires them into handlers with `html/template` + htmx + Alpine.js; all assets are `embed`ded. Everything that needs root goes through the sudo helper from Plan 2; communication with the ES wrapper happens only through files in `/run/emulationstation/`.

**Tech Stack:** Go ≥ 1.25 (stdlib `net/http` with pattern routing, `http.CrossOriginProtection`), `golang.org/x/crypto/bcrypt`, `github.com/godbus/dbus/v5`, htmx 2.0.4, Alpine.js 3.14.8, Tailwind CSS v4.1.11 (standalone CLI).

**Spec:** `docs/superpowers/specs/2026-10-27-emulationstation-image-design.md` (sections 5.1, 5.5, 6, 7)

## Global Constraints

- **No git commands that write** (no `git add/commit/push/...`). Every "Checkpoint" step only lists the changed files for the user.
- Module path `emulationstation/webui`, directory `webui/`; `go 1.25` in `go.mod`; `CGO_ENABLED=0` must build.
- Only the two external Go dependencies above; frontend libraries as files under `webui/internal/web/static/vendor/` (htmx, Alpine), no CDN links.
- UI texts in simple English; dark design.
- Listen: `0.0.0.0:11944`, TLS only (MinVersion TLS 1.2). Certificate `/etc/emulationstation-web/tls/server.crt`, key `/etc/emulationstation-web/tls/server.key`.
- Configuration `/etc/emulationstation-web/web.conf`, format `KEY=VALUE` per line, mode 0600. Default credentials `zocken`/`zocken` (set at build time in Plan 2).
- A failed login produces **exactly** the log line `auth failure from <ip>` on stderr (journal; the fail2ban filter in Plan 2 matches `auth failure from <HOST>$`). `<ip>` has no port, IPv4-mapped IPv6 as IPv4.
- File contract with the ES wrapper (Plan 2), directory `/run/emulationstation/`:
  - `state`: one line, tab-separated: `es` | `game\t<system>\t<rom-abs-path>` | `stopped`
  - `hold`: exists → the wrapper does not restart ES
  - `launch`: `<system>\t<rom-abs-path>\n` → the wrapper starts the game and deletes the file
  - `es.pid`, `game.pid`: PID of ES and process group ID of the running game
- sudo helper `/usr/local/lib/emulationstation/priv` (Plan 2), called as `sudo -n <helper> <cmd> [arg]`, subcommands: `reboot`, `poweroff`, `apt-update`, `apt-upgrade`, `f2b-list` (output per line `<jail> <ip>`), `f2b-unban <ip>`, `journal <unit>` (units: `emulationstation-web`, `ssh`, `fail2ban`).
- RetroPie paths: ROMs `/home/emulationstation/RetroPie/roms`, BIOS `/home/emulationstation/RetroPie/BIOS`, ES config `/home/emulationstation/.emulationstation`, systems `/etc/emulationstation/es_systems.cfg`, input hook `/opt/retropie/supplementary/emulationstation/scripts/inputconfiguration.sh`.
- Gamelist location per system: `<roms>/<system>/gamelist.xml` if it exists, otherwise `<es-config>/gamelists/<system>/gamelist.xml` (default for new files).
- Upload limits (defaults): upload 4 GiB, unpacked total 8 GiB, max. 10 000 ZIP entries.
- Systems with an archive as ROM (never unpack): `arcade`, `fba`, `fbneo`, `neogeo`, `mame-libretro`, `mame-mame4all`, `mame-advmame`.

## Review Focus

1. **Disc games in a ZIP** (`.cue`+`.bin`, `.gdi`+tracks, `.m3u`+discs): referenced companion files must be copied too, even if their extension is not in the system list; only the main file gets a gamelist entry. → Tests in Task 6.
2. **Cross-site requests:** The browser sends Basic Auth credentials automatically; a foreign page must not be able to trigger `POST /system/reboot`. → Test in Task 13.
3. **Disk full / abort during upload:** partial files in staging are deleted, the user sees a clear error message, existing ROMs stay unchanged. → Test in Task 6.
4. **Missing or broken `gamelist.xml`:** missing → empty list; broken → show an error, do not overwrite the file. → Test in Task 5.
5. **File names with special characters** (umlauts, spaces, `..`, `/`, control characters) in upload and ZIP: umlauts/spaces are kept, path parts are removed or rejected. → Tests in Task 6.

- Produces:
  ```go
  var ErrUnsafePath, ErrTooLarge, ErrTooManyEntries, ErrUploadTooLarge error
  func SafeName(name string) (string, error) // base name; rejects "", ".", "..", control characters; umlauts/spaces are kept
  func Extract(zipPath, dest string, maxBytes int64, maxEntries int) ([]string, error) // rel. paths, flat (subfolders → base name)
  func Companions(primaryPath string) ([]string, error) // .cue: FILE lines; .gdi: column 5 from line 2; .m3u: non-empty lines; .ccd: .img/.sub with the same name

  type StagedFile struct {
      Name          string   // file name in staging
      Candidates    []string // system names
      SuggestedName string
      CompanionOf   string   // empty = main file
      Discarded     bool
      Reason        string
  }
  type Upload struct { ID string; Files []StagedFile }
  type Stager struct { /* cfg, systems, mutex, map[id]*Upload */ }
  func NewStager(cfg *config.Config, sys []systems.System) *Stager

  func (s *Stager) Get(id string) (*Upload, bool)

  type Choice struct { Name, System, DisplayName string; Skip bool }
  type Committed struct { System, RelPath, DisplayName string }
  // Commit moves files + companion files and writes gamelist entries; MUST run in es.Controller.WithESStopped.
  func (s *Stager) Commit(id string, choices []Choice, overwrite bool) ([]Committed, error)
  func DeleteROM(cfg *config.Config, system, rel string) error // file + companion files + gamelist entry
  ```
- ZIP decision in `Receive` (algorithm):
  1. Stream the file to `<Staging>/<id>/`, abort at > `MaxUploadBytes` (→ `ErrUploadTooLarge`).
  2. Not a `.zip` → one `StagedFile` with `Candidates` from the extension.
  3. `.zip`: read the entry names (without unpacking). If at least one entry has an extension of a system **without** `KeepArchives` (except `.zip` itself) → unpack; otherwise → keep as archive, `Candidates` = only `KeepArchives` systems.
  4. After unpacking: main files = files with a system extension; their `Companions` are marked with `CompanionOf` (even if the extension belongs to no system); everything else is `Discarded` with `Reason` "unknown file type".
  5. `SuggestedName` = `names.Clean(Name)`.
